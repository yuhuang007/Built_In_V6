## 1. 一句话状态

这是一个基于 **ESP32-P4 Function EV Board（用户称 P4X，399 套装）** 的听障双向沟通原型。目前稳定运行的是单板语音方向：

```text
普通人按住屏幕说话
  → P4X 板载麦克风采集
  → 板载 ESP32-C6 Wi-Fi
  → 火山引擎硬件对话智能体（ASR、对话、TTS）
  → 7 英寸屏幕显示字幕 + 外接扬声器播放回复
```

当前已烧录并提交的版本为：

```text
分支：master
提交：8402150 ui: remove local loopback control
开发板端口：COM20
界面：纯文字 UI；按住说话、松开结束；本地录音回放按钮已移除
```

其后的 `27c1f4a` 仅新增 10 月 7 日进度文档，不改变固件功能。

语音主链路已经恢复；用户最后的反馈是“目前没有大问题”，只观察到扬声器偶发轻微卡顿。已完成一次低风险的播放空闲阈值调整以缓解该现象，但仍需要连续多轮真人对话验收。

摄像头、手语识别、CS001 副板、千帆网关、云服务器均**没有进入当前稳定固件**，处于冻结状态。

## 2. 项目目标与阶段边界

### 2.1 最终项目愿景

项目面向聋哑/听障用户，建立双向沟通终端：

```text
方向 A：普通人 → 听障用户
普通人语音
  → 云端 ASR
  → 屏幕大字字幕

方向 B：听障用户 → 普通人
静态手势
  → P4 本地轻量分类
  → 候选文字（用户确认）
  → 云端 TTS
  → 扬声器播报
```

这里的“手语”第一版是可演示的**静态高频手势词表**，不是连续手语句子翻译。

### 2.2 当前迭代的严格范围

当前阶段只允许 P4X 单板参与：

- 火山硬件对话智能体是唯一实时云端语音链路；
- P4 负责音频采集/播放、触摸交互、字幕 UI，后续负责轻量视觉推理；
- C6 仅作为套装板载 Wi-Fi 协处理器，当前不修改其固件；
- 使用 SD 卡承载中文字体及后续模型/数据资产，运行期内存仍以 P4 的 PSRAM 为主。

### 2.3 当前明确冻结的内容

下列项不是“没有想到”，而是为了保护已恢复的语音主线，主动冻结：

- CS001/S3 副板、副屏与 UART 协议；
- 连续手语句子识别；
- 广角摄像头接入前的实时视觉功能；
- 原装 SC2336 的 ISP 实时预览实验；
- 百度千帆、`gateway/`、服务器、网页搜索、天气与日期注入；
- 把 ASR 文本再次提交给另一套 LLM 的双链路；
- 修改 C6 固件或用 C6 OTA；
- UI 美化大改。

这些项目可在后续阶段恢复，但必须从语音稳定标签创建独立分支，不能直接叠加到 `master`。

## 3. 硬件实物与已确认参数

### 3.1 主开发板与基础资源

用户持有的是 **ESP32-P4 Function EV Board / P4X 套装版**，不是 HDMI 方案。实际日志验证：

| 项目 | 已确认结果 |
|---|---|
| 主控 | ESP32-P4 rev 3.2，双核，400 MHz |
| Flash | 16 MiB，DIO，80 MHz |
| PSRAM | 32 MiB，200 MHz，启动测试通过 |
| 串口 | COM20，用于 P4 构建、烧录、复位与日志 |
| Wi-Fi | 板载 ESP32-C6，通过 ESP-Hosted/SDIO 与 P4 通信 |
| 存储卡 | 约 32 GB microSD，已安装在板载卡槽，中文字库已成功从 SD 卡加载 |

### 3.2 显示与触摸

| 项目 | 参数/结论 |
|---|---|
| 屏幕 | 套装自带 7 英寸显示屏，1024×600 |
| 连接 | 套装 MIPI-DSI 排线，**不是 HDMI** |
| 显示链路 | EK79007AD / EK73217BCGA 路线，2-lane MIPI-DSI |
| 触摸 | GT911 电容触摸 |
| 当前状态 | 显示、背光、LVGL、触摸坐标均已由用户实机确认通过 |

显示与触摸应继续复用官方 BSP 路径，不应自行重配 MIPI-DSI 引脚或面板寄存器。

### 3.3 音频

| 项目 | 参数/结论 |
|---|---|
| 编解码器 | ES8311 |
| 输入 | 板载模拟麦克风 → ES8311 ADC → I2S RX |
| 输出 | ES8311 DAC → 板载功放 → 用户已接的外接扬声器 |
| 音频控制 I2C | GPIO 7 (SDA)、GPIO 8 (SCL) |
| I2S | GPIO 9 (DOUT)、10 (LRCK)、11 (DIN)、12 (BCLK)、13 (MCLK) |
| 功放使能 | GPIO 53，由 BSP 控制 |
| 本地验证格式 | 16 kHz / 16-bit / 单声道 PCM |
| 当前默认增益/音量 | 麦克风约 30 dB，扬声器约 45% |

用户已确认本地录音回放清晰，说明麦克风、ES8311、I2S、扬声器接线和功放使能都正常。外接扬声器不要接到 I2S 数据 GPIO 上，应接套装的音频输出/功放接口。

### 3.4 摄像头

| 项目 | 状态 |
|---|---|
| 原装摄像头 | 套装 MIPI-CSI 相机子板；子板 PCB 丝印与资料指向 SC2336 路线 |
| 输出类型 | RAW（资料有 RAW8/RAW10 表述，实际需以驱动枚举结果为准） |
| 已发生验证 | 基础采集测试曾显示“摄像头采集正常，测试完成” |
| 未完成 | RAW → P4 ISP → RGB565 → LVGL 实时预览没有跑通 |
| 当前策略 | 摄像头代码与配置从稳定语音构建路径隔离，当前不初始化 CSI/ISP |
| 广角摄像头 | 用户已购买/等待到货；到货前先不继续动视觉主线 |

用户也询问过 Type-C 集成摄像头/麦克风/扬声器模块。它不能被当作原装 MIPI 摄像头的直接替代品：USB 摄像头需要 USB Host/UVC 支持、供电和不同的软件栈，会显著扩大调试面；当前没有纳入方案。

### 3.5 曾使用 USB-TTL 的背景

前期曾因 C6/固件恢复需要使用 USB-TTL 下载器，用户已完成接线、识别下载模式、复位等操作。C6 后来恢复可工作，P4 当前通过 COM20 正常使用。**以后不要为普通语音问题重新刷 C6**；只有明确、可复现的 C6 兼容性故障且已经有可恢复固件时才单独操作。

### 5.3 云端授权的重要事实

旧火山设备的基础版时长已经用尽。火山控制台中的多个 License 是**可激活多个独立设备**的资源，不是给一个旧设备叠加使用时长。因此当前通过 `p4x_device_override.h` 指定新的设备身份，让 SDK 自动动态注册，才恢复语音会话。

如果将来再次出现“机器人入房后约一秒离房、欢迎语/会话立即截断”的模式，优先检查：

1. 火山控制台产品/设备授权和剩余时长；
2. 当前 `p4x_device_override.h` 是否指向已分配 License 的可用设备；
3. 新设备是否在产品和智能体关联下正确激活；
4. 再看网络和 RTC 日志。

不要先改 I2S、VAD、摄像头或 SNTP。

## 6. 当前可用语音链路

### 6.1 架构

```text
手指按住屏幕
  ↓
LVGL 触摸事件
  ↓
P4 语音状态机（main.c）
  ↓
ES8311 板载麦克风采集 PCM
  ↓
板载 C6 / ESP-Hosted SDIO / Wi-Fi
  ↓
火山硬件对话智能体
  ├─ 流式 ASR 字幕返回
  ├─ 对话生成
  └─ 流式 TTS PCM 返回
  ↓
P4：字幕更新 + ES8311 扬声器播放
```

云端采用火山硬件对话智能体完成 ASR、对话和 TTS。P4 不接千帆、不接网页搜索，也不会再把已识别的 ASR 文本二次调用 `volc_send_text_to_agent()`，以避免一段语音被回答两次。

### 6.2 用户操作方式

1. 开机后等待屏幕进入“云端语音已就绪”或等效就绪状态；
2. **按住**屏幕上的说话按钮；
3. 对麦克风说话；按住期间屏幕应显示 ASR 实时字幕；
4. **松开**按钮，固件补发约 240 ms 静音尾音，由云端 VAD 结束这一轮；
5. 屏幕显示回复字幕，同时/紧邻首个可播放 PCM 开始扬声器播报；
6. 回复播报中再次按住，可以打断旧回复并提出新问题；
7. 回复结束后自动回到就绪状态。

### 6.3 状态机要求

当前语音状态机的有效路径：

```text
RECOVERING --云端就绪--> IDLE
IDLE --按住--> RECORDING
RECORDING --松开--> FINISHING
FINISHING --尾音发送完--> THINKING
THINKING --首个回复 PCM--> ANSWERING
ANSWERING --回复结束--> IDLE
ANSWERING --再次按住--> 打断旧播放 → RECORDING
```

必须防止以下历史回归：

- 对话已经结束却永久提示“当前对话尚未结束”；
- 回答中无法按住打断，只提示“正在理解上一句话”；
- ASR 文本被再次送 LLM 导致两次回答或日期自相矛盾；
- 回复文字全部出现后才播放声音；
- 本地诊断录音与云端播放争抢扬声器；
- 云端短暂 PCM 帧间隙导致 I2S 反复关闭/打开。

### 6.4 已做的稳定性处理

- VAD 保留已验证的两秒语音尾部策略（提交 `525ca88`）；
- RTC 恢复过程重用已经同步的时钟，避免无谓重复时间同步（提交 `07ec9c8`）；
- ASR 超时可回收陈旧云端会话（提交 `60b5bcc`）；
- P4 复位后保持可用串口诊断（提交 `a6d3efc`）；
- PCM 队列的播放空闲关停阈值由 500 ms 调到 1500 ms（提交 `f5c1a1a`），减轻短暂帧间隔造成的卡顿；
- 本地录音回放按钮已从用户 UI 删除（提交 `8402150`），内部诊断函数仍保留，默认不会触发。

### 6.5 资源边界

- 当前应用二进制约 `0x245420`；最小应用分区 `0x300000`；约保留 `0xBABE0`（约 24%）余量；
- 音频实时任务的优先级高于 UI 和未来视觉任务；
- 不在 RTC 回调栈中分配大数组；
- 摄像头缓冲以后必须使用预分配 PSRAM，并且不能与音频 DMA 共用；
- 语音模式不初始化 CSI/ISP；
- 当前云端下行播放参数在运行日志中为 8 kHz / 16-bit / 单声道 PCM 路线；本地录音诊断为 16 kHz / 16-bit / 单声道。

## 11. 后续路线图

### 阶段 0：当前先完成语音稳定验收

不改代码，做测试：

| 类别 | 内容 |
|---|---|
| 固定短句 | 你好；我需要帮助；请说一句测试语音；我想喝水；请用一句话介绍自己 |
| 自由提问 | 5 次 |
| 每次验收 | 按住期间有 ASR；松开后只有一次回复；字幕与声音完整；无重启；可进入下一轮 |
| 打断验收 | 回答中再次按住，新问题应打断旧回答并正常完成 |
| 网络验收 | 空闲状态断 Wi-Fi 再恢复；不重启 P4、不刷 C6，最终恢复为可说话状态 |

10 次均通过后，为当前语音提交打标签，例如：

```powershell
git tag -a voice-baseline-20261007 -m "Verified P4X voice baseline"
```

仅在 Git 远端认证完成后再推送该标签。

### 阶段 1：原装/广角摄像头基础预览（独立分支）

广角摄像头到货后先核对：

- FPC 针数、引脚定义和插接方向；
- MIPI lane 数；
- 电源轨和电压；
- I2C 地址、XCLK；
- 输出 RAW 位宽/格式；
- ESP-Video 是否已有该传感器驱动；
- 它是只换镜头，还是完整传感器模组替换。

接口外形相似不代表可以直接通电。先用原装 SC2336 在独立分支跑通最小 `RAW → ISP → RGB565` 管线。建议顺序：

1. 只枚举视频节点、传感器格式、实际分辨率；
2. 不接 LVGL，只做连续采集和帧率/内存统计；
3. 启用 ISP 输出，确认 RGB565；
4. 以低分辨率、低帧率复制到独立 PSRAM 缓冲；
5. 再接 LVGL；
6. 连续 60 秒预览，无重启、无音频崩溃；
7. 连续启动/停止 5 次，无 MMAP/PSRAM 泄漏；
8. 才评估广角模组适配。

### 阶段 2：静态手势 MVP

只做 10–20 个固定静态词，例如：

```text
你好、谢谢、请、是、否、需要帮助、再见、喝水、厕所、紧急求助
```

先写采集规范：固定距离、光照、背景、手势朝向、每类样本量和独立验证集。然后选可量化并部署到 ESP32-P4 的轻量分类模型。运行策略：

- 仅手语模式启动摄像头和视觉任务；
- 多帧一致才显示候选词；
- 用户确认后才请求 TTS；
- 低置信度显示“未识别，请重试”，不直接播报；
- 第一版不承诺连续手语识别。

### 阶段 3：双板/扩展功能（最后再做）

只有单板语音与静态手势都稳定后，才重新评估：CS001 副板、副屏、UART 协议、更多云端工具或网关。届时必须以原始项目说明为准重新写资源预算和接口协议。

## 最终交接结论

当前最正确的策略不是继续堆叠功能，而是先守住已恢复的单板语音闭环：确认新火山设备 License 可用、完成 10 次回归、建立标签和远端备份。随后摄像头预览、静态手势分类、广角模组适配都要独立分支、独立配置、独立验收。这样即使视觉实验失败，也不会再次破坏已经可用的字幕和语音播报。
