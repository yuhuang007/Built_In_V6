这证明直接进入首页是触发 60 秒异常上限，而不是字库已经完成。

先本地提交纯数字诊断 `9d88d6c`，随后 `d057ea2` 修正计数初始化位置；修正后才构建和烧录。
诊断区分底层读取、定位与重新取得显示锁的耗时，并每个进度变化或约 5 秒报告一次阶段。
只输出数字状态，不输出字体文件内容、私密配置或识别原文。COM20 每次仅一个观察进程，结束时关闭。

诊断版测得：

| 项目 | 耗时 |
| --- | ---: |
| 14px 索引加载 | 55,010 ms |
| 其中底层读取 | 2,131 ms |
| 其中底层定位 | 288 ms |
| 其中等待显示锁 | 52,224 ms |
| 单次最长等待显示锁 | 653,858 us |
| 启动页退出 | 60,470 ms，`fonts_done=0` |
| 全部字体准备结束 | 71,454 ms |

锁定 LVGL 9.6 的 `src/core/lv_refr.c` 会先绘制活动 screen，再无条件绘制 top/sys layer。
旧启动页位于 `lv_layer_top()`，没有让原首页停止绘制。首页 SD 字库绑定后，每次 GIF/状态失效区域
都可能连带绘制其下的首页文本，动态字形读卡在渲染任务持有显示锁期间发生。
这与到首页字体完成阶段后明显变慢、加载任务大部分时间等待显示锁、遮罩删除后加载迅速完成一致。
不能再把这次卡顿简单归因于后台字库索引读卡本身。
