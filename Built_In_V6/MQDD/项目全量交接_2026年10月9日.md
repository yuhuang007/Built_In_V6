## 1. 项目目标、当前范围和冻结边界

这是基于 **ESP32-P4X / ESP32-P4 Function EV Board** 的听障双向沟通原型，而不是完整量产系统。

```text
方向 A：普通人 → 听障用户
板载麦克风 → P4 → 板载 C6 Wi-Fi → 火山硬件对话智能体
       → 实时 ASR 字幕 + 对话回复字幕 + TTS PCM → 屏幕 / 外接扬声器

方向 B：听障用户 → 普通人（后续）
MIPI-CSI 摄像头 → P4 本地静态手势分类 → 候选文字（用户确认）
          → 火山 TTS → 外接扬声器
```

重要产品边界：第一版“手语翻译”只是**静态高频手势词表**（建议 10–20 项）的本地分类与确认，不是连续手语句子翻译。现在的“手语翻译”页面仅完成摄像头预览与模式切换，**尚未接入任何手势模型**。

当前明确冻结，除非用户明确要求，不要修改、启用或扩展：

- ESP32-C6 固件、C6 OTA 或 USB-TTL 烧录；
- SNTP 的既有稳定路径；
- 千帆、`gateway/`、云服务器、网页搜索、天气/日期注入，或第二条 LLM 链路；
- CS001/副屏/UART 方案；
- 将 USB 摄像头方案和当前 MIPI-CSI 方案混合；
- 大幅 UI 美化；
- 将语音、摄像头、网络、音频状态机同时改动。

以前曾因把摄像头、ISP、网络恢复和语音一起改入主程序，造成欢迎词中断、松开后卡住和无回复。之后建立了 Git 基线与独立分支策略；不能重演。

## 5. 三条运行链路的结构与正确行为

### 5.1 火山硬件对话智能体：原语音主页

原语音链路是唯一实时对话链路：

```text
用户按住 → P4 麦克风采集 PCM → C6 Wi-Fi → 火山硬件对话智能体
         → 逐步 ASR 字幕 → 用户松开并补尾帧 → 云端单次回复 / TTS PCM
         → 回复字幕与 ES8311 扬声器播放
```

有效状态路径：

```text
RECOVERING → IDLE → RECORDING → FINISHING → THINKING → ANSWERING → IDLE
                                      ↑                 │
                                      └────回答中再次按住打断──┘
```

必须维护：按住期间可见 ASR；松开后只回复一次；首个可播放 PCM 到来时开始显示助手字幕/播放；回答中再次按住可打断；下一轮不会永久提示“上轮未结束”。云端状态通知可能滞后，物理按压优先于陈旧 `THINKING/ANSWERING` 状态。

早期旧设备的云端可用时长耗尽曾表现为机器人进房约一秒离开、欢迎词截断、无回复。正确处理是检查火山控制台授权/当前设备身份，并在本地覆盖文件中切换到获授权的设备名；不要先改麦克风、I2S、摄像头或 C6。

### 5.2 独立豆包实时 ASR：语音转文字页

首页“语音转文字”与上述对话链路不同：

```text
按住 → 16 kHz / 16-bit / 单声道 PCM → 豆包双向 WebSocket ASR
松开 / 触点移出 → 负序号末帧 → 最终文本留在页面
```

- 每轮最多 60 秒；录音只在内存中暂存，不落盘；
- 200 ms 包（6,400 字节）、gzip、官方二进制序号帧；
- 最终文本不再提交 LLM，也不启动 TTS；
- 首页/返回时保留原 RTC 会话和零 PCM 节奏，正常网络下不重新欢迎；
- WebSocket Upgrade 需要 `CONFIG_WS_BUFFER_SIZE=4096`，默认 1024 无法容纳实测约 1,228 字节响应头；
- WebSocket 底层请求头日志被关闭，绝不能打开，因为其中可能带鉴权头。

实现位于 `firmware/p4_main/main/doubao_asr.c`、`doubao_asr.h` 和 `speech_to_text_mode.c`。协议离线检查：`tests/test_doubao_asr_protocol.py`；它不等于实机验收。

### 5.3 手语翻译：当前仅相机预览和无重启切换

主页点击“手语翻译”后：

1. 只在实际录音、尾帧处理、字体同步、云端注册/恢复等真实工作进行时拒绝进入；云端陈旧状态或扬声器仍开不应永久阻止切换。
2. 摄像头工作任务先停止本地播放、请求打断当前回答，但**不**销毁 RTC 会话。
3. 相机运行时不采集麦克风、不上传图像，保留 RTC 与空闲零 PCM 节奏，抑制语音 UI/播放。
4. 返回时，工作线程依次释放 CSI、AWB、ISP、PPA、SCCB、采集/预览缓冲，之后恢复语音 screen。
5. 若 Wi-Fi/RTC 仍在线，直接回 `IDLE`，不重新注册、不欢迎；若真实掉线，才走已有恢复路径。

不得把销毁相机资源放在 LVGL 按钮回调中，不得为返回调用 `esp_restart()`，不得在模式正常切换时 `volc_stop()` / `volc_destroy()`。这几种旧做法分别造成重启、欢迎词重播或资源竞争。

## 7. 字库、SD、滑动和启动预准备

### 7.1 字库文件与用途

SD 卡 `fonts/` 目录应有：

| 文件 | 用途 | 大小 |
| --- | --- | ---: |
| `P4ZH14.BIN` | 旧共享 14px；原语音首页继续使用 | 保留，不覆盖 |
| `P4Z14V2.BIN` | 独立转写页状态/按钮 | 2,954,524 bytes |
| `P4Z28V2.BIN` | 独立转写页原生大正文 | 10,333,116 bytes |

文件名是 FATFS 8.3 兼容命名。V2 两套字体实际含相同的 29,861 个字符：常用中英文、CJK/全角标点、数学、货币、单位、箭头等；不承诺 emoji、所有 Unicode 或罕见汉字。生成资产、实际覆盖、SHA 与许可证见：

- `assets/fonts/SD-FONTS-V2.md`
- `assets/fonts/sd-fonts-v2-manifest.json`
- `assets/fonts/SD-FONTS-DEJAVU-LICENSE.txt`
- `assets/fonts/P4-FONT-LOADER-LICENSE.txt`

转写页使用原生 28px、512 项/768 KiB 上限的 PSRAM 字形缓存。首次遇到字形仍会从 SD 读取，命中后滚动不再重复读取该字的位图；因此“滑动改善”不等于所有字符均不产生首次读卡延迟。

### 7.2 安装与快速校验

首次缺失 V2 字库时，进入转写页才会用局域网分段安装：16 KiB 分段、临时文件独占创建、大小/SHA 校验、`fsync` 后重命名。失败或取消只清理本轮创建的未完成文件，绝不覆盖旧字体或预先存在临时文件。

成功后，板端在 NVS 命名空间 `sd_font_v2` 保存版本哈希、大小与 FAT 修改时间。以后进入转写页和重启后元数据相同就直接加载，不再读约 13 MB 做全量 SHA；这不是逐次介质完整性扫描，静默损坏/同时间戳换卡不保证发现。

用户已确认双字库达到 100% 后能正常进入转写页并返回首页。传输服务已关闭；之后不需要电脑服务，也不应每次启动传字库。

### 7.3 启动后台预准备与 GIF

启动页会并行：显示/音频初始化、首页基础字体、Wi-Fi/网络准备，以及已存在 V2 字库的索引解析/缓存建立。缺失 V2 字库**不会**在开机自动下载，仍只在用户进入转写页时安装。

进度是完成的真实阶段权重，不是时间伪造：

```text
显示与启动页 5% + 音频 15% + 首页字体 15% + Wi-Fi 15% + 网络准备 10%
+ 14px 索引 15% + 28px 解析 24% + 缓存成功 1% = 100%
```

GIF 资源在 `assets/startup/`：用户提供的 700×700 GIF 被保留在下载目录；工程使用派生的 `loading.gif`，320×320、60 帧、60 ms、3.6 秒循环、黑色背景，183,815 bytes。`manifest.json` 记录来源摘要、帧时序和 SHA；`font_startup_zh.c` 是不依赖 SD 的 24px 状态文案字库。

`loop_count=0` 才表示 LVGL 无限循环，负数会在一轮后暂停。启动页删除后会释放 GIF 画布/缓存。应保持黑底、单行中文状态说明、下方进度条；完成时不等 GIF 播到边界，直接进入首页；欢迎词必须由首页显示后的下一轮 LVGL 定时器放行。

### 7.4 最新启动卡顿修复（待验收）

用户反馈 `8ae0c0e` 到约 60% 会卡顿，随后不连贯地跳首页。确认的代码路径是：此前大字库索引读取仍持有显示锁，且启动页无条件 20 秒退出，即便字体没完成。

`50404d9` 的限定修复：

- `p4_font_loader.c` 给尚未发布的字体使用私有文件驱动副本；仅底层 stdio 读/定位期间释放显示锁，每次最多 16 KiB；LVGL 缓存、分配与元数据解析仍持锁；
- 发布字体前恢复原驱动，避免绘制回调在未知上下文解锁或持有栈指针；不改全局 LVGL 文件驱动；
- 14px/28px 进度由真实已解析字形数报告，进度条使用平滑动画；
- 字库仍在解析时不再因 20 秒强制跳首页；字库完成后网络仍可在 20 秒回退；整体保留 60 秒异常上限；
- 正常完成值展示一个约 200 ms UI 间隔，再关闭启动页并放行欢迎词。

这不是已验收结论。新 AI 应先拿到用户的连续观察结果，再决定是否需进一步优化；不能在没有数据时胡乱降低 GIF 帧数、修改 LVGL、禁用字库预加载或扩大超时时间。

## 10. 每次开发的强制方法

用户的硬规则必须照做：

1. 先读本文件、最近进度和验收表；运行 `git status --short --branch`、`git log --oneline -n 10`。
2. 工作区若有不属于本任务的改动，停止并查明来源；不要用任何破坏性 Git 命令抹掉。
3. 一次只改一个子系统，例如只改启动加载、只改相机预览，不能顺手改音频/网络/C6/UI。
4. 先做本地小提交；再构建；检查应用分区余量、`dependencies.lock` 和 profile 配置；最后才烧录 COM20。
5. 烧录后只验证该改动及必要的基础回归；没有用户实机确认，不能宣称功能完成。
6. 每次形成证据后更新 `MQDD/` 日报并提交文档；注明“已构建/已烧录/用户确认/待验收”的不同状态。
7. 不使用 `git reset --hard`、`git checkout --`、大范围删除或覆盖操作；文件编辑优先 `apply_patch`。
8. 不将秘密写入源码、提交、日志、日报、截图或回答；底层 RTC/WS 日志不能为了排障随意打开。

建议的最小流程：

```text
明确用户目标 → 阅读交接/状态 → 只选一个子系统 → 小改动
→ git commit → build → 依赖锁/分区检查 → flash COM20
→ 用户实机验证 → 记录日报与验收状态
```

`COM20` 监视器必须一次只开一个。串口诊断只输出白名单状态、数字耗时、错误码、内存/帧率；不保存原始云端消息、识别文字、SSID、请求头、Token 或密钥。观察结束必须释放串口。

## 12. 重要历史结论和禁止回退的方案

- 云端 ASR 文本不可再二次发送给另一套 LLM；会造成双回复、冲突日期和不可控延迟。
- 日期/天气/搜索/千帆/服务器不属于当前单板原型；不要因为模型回答不确定就接入这些系统。
- “启动后自动发送一段诊断文字”是历史临时实验，不能恢复为产品行为。
- 本地录音回放入口已经从用户 UI 移除；可以保留内部诊断，但不得重新作为普通入口。
- 返回语音时重启整板是旧过渡方案，已被无重启资源交接替代；不得恢复。
- 返回语音时销毁 RTC、导致重新注册/欢迎，是已修复的体验回归；不得恢复。
- 相机全屏/静态控件相互重绘曾导致很低显示帧率；不要为了改布局重新让控件和每帧图像交叠。
- 早期相机 RAW 直接按 RGB565 请求失败；正确路径是 `SC2336 RAW8 → CSI → ISP → RGB565 → PPA → LVGL`。
- `U+2026` 省略号曾在旧字库变方框；公共状态文案应继续避免旧字体不支持字符，转写正文优先使用 V2 字库。
- 组件管理器的“自动更新”不是安全的构建行为；锁文件发生漂移必须先调查。

## 13. 下一步路线图与严格顺序

### 当前立即待办：验收 `50404d9`

5. 再快速进入一次“语音转文字”，确认不会再次全量安装/校验；
6. 再做一轮原语音和一次相机入口/返回，确认无基础回归。

只有拿到反馈后，才决定要不要继续优化启动读取或进度观感。不要在反馈前扩展到相机、ASR 或 UI 新需求。

### 随后：补足现有验收，而不是继续堆功能

1. 原语音：完成/记录 10 轮固定短句与自由提问，包含字幕、单次回复、扬声器、回答中打断、无重启；可另测断 Wi-Fi 后恢复。
2. 转写：10 轮按住/松开，检查中文/英文标点、大字/长句滑动、空按/断网/返回、5 次进入退出后的 PSRAM；返回后再测原语音。
3. 相机：至少 60 秒预览、5 次进入/返回、启动中返回/失败页返回、返回后语音和打断；记录 `timing: shown_fps/cache_us/scale_us/display_us` 和 PSRAM，不记录敏感数据。

### 手语 MVP（上述稳定后才开始）

1. 先冻结摄像头输入规格，制定固定光照、背景、距离、手势朝向和训练/测试集采集规则；
2. 只选 10–20 个高频静态词，例如你好、谢谢、请、是、否、需要帮助、再见、喝水、厕所、紧急求助；
3. 选择可量化、可部署到 P4 的轻量分类模型，先做离线验证和资源预算；
4. 运行时只在手语模式启相机和推理，多帧一致才显示候选；
5. 用户确认后才请求 TTS；低置信度显示“未识别，请重试”，不能直接播报；
6. 模型/数据/推理必须在从已验证版本创建的新分支进行，不能污染 `master`。

广角模组真正适配也必须在此阶段前先完成单独硬件确认和最小采集，不可仅凭商品描述推断兼容。
