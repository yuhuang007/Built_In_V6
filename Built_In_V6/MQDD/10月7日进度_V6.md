## 1. 今日结论

1. 用户已确认纯文字实时语音闭环通过稳定性验收，稳定基线标签为 `voice-baseline-20261007`。
2. 摄像头开发已从语音稳定标签建立独立分支，未直接修改 `master`。
3. SC2336 已完成独立实时预览：1920×1080 RAW8、双 MIPI CSI lane、约 30 fps 采集，通过 P4 ISP 输出 RGB565，再由 PPA 以 0.5 倍缩放为 960×540。
4. 960×540 画面居中显示在 1024×600 屏幕上，左右各保留约 32 像素、上下各保留约 30 像素黑边，避免为了铺满屏幕再次裁切传感器视野。
5. 用户已确认：镜像方向正确，移动时的撕裂和果冻感明显改善，白平衡不再明显发黄，切换全画幅后视野明显变宽。目前只观察到画面略暗。
6. 全画幅版本最初出现循环重启。最终根因是 PPA 全分辨率缩放调用链超过原 camera profile 的主任务栈，并非摄像头损坏或 PSRAM 不足。主任务栈调整为 16 KiB 后，硬件栈守卫与 FreeRTOS canary 均保持启用，实机连续运行超过 60 秒无重启。
7. 当前开发板烧录的仍是独立 `p4_camera_probe` 验证固件，因此开机直接进入摄像头画面。这不是最终产品交互。
8. 用户已明确最终交互要求：开机进入原语音界面，在原界面新增“手语翻译”按钮；只有点击该按钮后才进入摄像头画面。
9. 今日在停止开发前仅创建了后续集成分支 `feature/sign-language-mode`，尚未修改主程序、构建或烧录集成固件。

## 3. 摄像头硬件与格式确认

| 项目 | 实测/配置结果 |
|---|---|
| 传感器 | SC2336，PID `0xcb3a` |
| SCCB 地址 | `0x30` |
| 接口 | MIPI CSI-2，2 lane |
| 传感器模式 | `MIPI_2lane_24Minput_RAW8_1920x1080_30fps` |
| CSI lane rate | 336 Mbps |
| ISP 输入/输出 | RAW8 → RGB565 |
| 采集分辨率 | 1920×1080 |
| 显示分辨率 | 960×540，居中置于 1024×600 屏幕 |
| 缩放 | PPA SRM，X/Y 均为 0.5 |
| 采集缓冲 | 3 个 1920×1080 RGB565 PSRAM DMA 缓冲 |
| 显示链路 | 独立 probe 使用 DSI 双缓冲 |
| 水平镜像 | 已在传感器侧修正，Bayer 顺序保持 BGGR |
| 白平衡 | ISP AWB + WBG，持续统计并更新增益 |

此前 1024×600 传感器模式本身采用中心裁切窗口，只使用约 1056×608 的有效区域，水平覆盖约为完整 1920 宽度的 55%，因此即使镜头标称 120°，屏幕上也会明显感觉视角变窄。切换到 1920×1080 全画幅后，用户已确认视野变宽。

## 4. 今日实机问题与修复

### 4.1 开机无画面与早期预览问题

摄像头开发初期先完成独立 probe 的显示和采集链路，避免直接污染稳定语音主程序。随后逐项处理：

- DSI 双缓冲与全速预览；
- 水平镜像方向；
- 镜像后的 Bayer phase；
- 移动时的撕裂和果冻感；
- 自动白平衡及其 IPA 依赖；
- AWB 收敛阈值。

用户实机反馈表明上述问题已明显改善或得到确认。

### 4.2 全视野版本循环重启

切换至 1920×1080 并增加 PPA 缩放后，开发板曾反复闪屏重启。日志过程如下：

1. 传感器能够正常识别为 1920×1080 RAW8；
2. 三个全分辨率缓冲能够成功分配，PSRAM 并未耗尽；
3. 第一帧或约第 30 帧附近触发栈保护；
4. 临时关闭硬件栈守卫后，FreeRTOS canary 明确报告：

```text
***ERROR*** A stack overflow in task main has been detected.
```

5. 将 camera profile 的主任务栈从 3584 字节提高到 16384 字节，并重新启用硬件栈守卫后，循环重启停止。

当前保护配置：

```text
CONFIG_ESP_MAIN_TASK_STACK_SIZE=16384
CONFIG_FREERTOS_ISR_STACKSIZE=4096
CONFIG_ESP_SYSTEM_HW_STACK_GUARD=y
CONFIG_FREERTOS_CHECK_STACKOVERFLOW_CANARY=y
```

## 5. 最终 60 秒日志验收

```text

```

实机连续日志结果：

- 60 秒内显示 1304 帧；

- PSRAM 长时间稳定剩余约 14.5 MB；
- AWB 持续运行；

- 用户随后确认开发板不再反复重启，画面视野也更宽。

队列中的 `dropped` 计数持续增长，是因为采集约 30 fps，而当前全分辨率 PPA + 显示约 22 fps，长度为 1 的最新帧队列主动丢弃旧帧；这避免积压和延迟，但后续集成时仍应观察实际流畅度。

## 7. 下一步准确顺序

下次从 `feature/sign-language-mode` 继续，按以下顺序执行：

1. 保持开机默认进入原 `p4_main` 纯文字语音界面；
2. 在原界面底部新增“手语翻译”按钮，不大改整体 UI；
3. 将已验证的 SC2336/CSI/ISP/PPA 管线封装为按需启动模块；
4. 点击“手语翻译”后才申请摄像头和 PSRAM 帧缓冲，并切换到 960×540 预览界面；
5. 提供明确的“返回”入口；第一阶段可以通过受控重启回到语音主界面，之后再实现无重启资源释放；
6. 摄像头模式启动前必须确认当前没有录音或回复播放，避免与音频实时任务争抢资源；
7. 集成改动必须先本地提交，再构建；检查主程序分区余量和 `dependencies.lock` 后才允许烧录；
8. 上板后先验证开机默认 UI，再验证按钮进入摄像头，最后完整回归语音闭环；
9. 上述交互由用户实机确认后，才处理画面略暗；亮度调整不得与 UI/模式切换合并到同一次提交。
