# 灵译通项目工作约定

适用于本目录及子目录。当前用户明确指令优先于历史方案；以下约定不扩大操作授权。

- 处理本项目的开发、排障、模型实验、训练电脑任务和交接时，使用 `.agents/skills/lingyitong-development/SKILL.md`。普通知识问答不启动完整开发流程。
- 开工前简述目标、改动范围、任务和对应验证方式；小修改用简短清单即可。目标明确时自主推进，不反复确认已授权事项。
- 实施前检查 Git 状态及近期提交，保留未知改动、未跟踪文件和可用基线。不得抹除用户文件或自动推送远端。
- 默认一次处理一个相关子系统；必要的跨模块改动说明依赖并逐步验证，避免无关重构。
- 从 MQDD 最新相关记录和实际证据判断现状；源码、构建、板上固件、模型及反馈版本分别记录。历史任务和停工记录按当时语境理解，不自动续跑，也不阻止用户后来明确授权的任务。
- 固件沿用项目 `.idf-build-env` 和 `tools/Invoke-P4Build.ps1`，产品构建显式使用 `-Profile sign`。按项目约定先本地提交功能，再标准构建、核对锁/配置/分区，烧录限本轮授权范围；纯文档不构建、不烧录。
- 验证覆盖与改动相称；编译、宿主测试、烧录及短时无异常不能代替实际功能验收。报告真实执行的检查及未覆盖项，不用测试数量替代质量。
- 训练电脑由用户转交完整任务与返回成果；不将训练机路径当作本机路径，不自行远控或续跑旧训练任务。
- 不把秘密、原始聊天/串口正文、私人影像写入 Git 或交付；日志优先使用既有脱敏观察工具，结束后释放串口。
- 资料按任务读取，复用既有脚本和结果；不每轮全量审计、重复训练或重写全量交接。用户停止后停止相关工作。
