## 3. 核实与采集门槛

目前缺少手语核实人员，先完成本方案；正式标签和采集门槛保持待满足。可继续核对公开规范来源及许可，但真实参与者数据采集需另行明确任务与同意。

开始真实采集前必须有：

- 已核实词条与可用的动作示范；首批范围由用户确认。
- 参与者知情同意：采集用途、拍摄部位、存储位置、访问人员、是否训练/展示、保留时间及退出删除方式。默认本机使用，公开展示和外发单独确认。
- 确定实际相机模组、固定支架、朝向、镜像约定和覆盖范围；未来若换模组需重新验证。
- 核实可覆盖双手及必要面部/身体信息，记录工作距离与光照实测值。
- 明确采集工具的范围；当前预览没有已验收的保存/导出功能，不将“看到画面”写成“数据已采集”。

不默认录音，不拍聊天页、密钥配置或他人屏幕。参与者真实姓名/联系方式和同意记录与匿名数据索引分开管理，绝不放入Git或进度文档。

## 4. 采集设计与最小元数据

先录完整动作片段，再根据核实结果标注动作起止。静态类只从真正稳定区间取帧；相邻帧作为同一次试验的一部分，不计为独立样本。动态类保留起始、运动、结束过程。建议试采每段3–6秒，仅为操作起点；实际时长以完整表达为准。

建议先尝试相机距参与者0.6/0.9/1.2米，确定双手、必要上身/面部均完整且细节可辨的范围；这些是试采点，不是已验证使用距离。两种以上背景、正常及偏暗光照、正向及小幅侧向取景；记录实际参数，不以“室内正常”代替。任何裁剪不得切掉有语义的手、面部或身体关系。

每次独立试验从休息姿态开始，完成一个表达再放下手；同一类别分批穿插，避免连续录制时背景或服装成为类别线索。覆盖惯用手、左右手变体及身体差异需由核实人员确认，不能随意镜像增强造成词义改变。

| 元数据字段 | 内容 |
| --- | --- |
| participant_id / session_id / trial_id | 匿名参与者、独立采集批次、完整动作试验编号 |
| candidate_id / label_id / label_version | 候选核实时label_id可空；正式训练需冻结版本 |
| camera_profile / firmware_commit | 相机模组、参数版本与实际板上功能提交 |
| frame_format / width / height / mirror | 实际导出格式、尺寸、色彩及镜像约定 |
| distance / lighting / background / viewpoint | 实测距离、光照描述或测量值、背景、朝向 |
| handedness / variation | 惯用手及已允许的表达变体 |
| start / end / quality / exclusion_reason | 完整动作区间、稳定区间或关键阶段、质量与排除理由 |
| consent_ref / source_ref / reviewer_id | 本机授权索引、动作来源、匿名复核编号 |
| relative_path / sha256 / split | 数据相对位置、哈希及冻结后的集合归属 |

实际路径、原始人物画面和授权记录保存在后续约定的本机私有数据目录，位于仓库之外。仓库只放空模板、规范与不含真实人物信息的统计；本轮不创建真实数据目录，也不复制任何秘密。退出请求需涵盖原片、派生帧、缓存和备份；已训练模型的处理方式需在采集前说明。

## 5. 正例、负例与质量审查

正例覆盖多位参与者、不同session、距离、背景和光照。负例至少含无手、休息姿态、进出视野、两词间过渡、非词表真实手语、日常挥手/抓物/整理衣服、遮挡和不完整表达。针对“再见”等候选尤其核对日常动作混淆，不只用空背景作负例。

低质量样本记录原因后排除或单列压力测试集，不默默删除后只报告最佳结果。标注需复核：错误动作、裁切、运动不完整、来源不清或标签分歧不能作为可靠正例。姿态/关键点前端失败同样纳入结果，不从统计中隐藏。

建议先以3位参与者、每人2个独立session、每类每session约10次独立试验检验采集流程（每类约60次）。这是试采预算，尚不能证明跨人泛化；样本量根据学习曲线和失败场景增长。没有足够独立参与者时明确标为试验结果，不宣称面向新用户可用。

## 6. 划分与可复现规则

正式跨人评估建议至少6位独立参与者，初始可按3人训练、1人验证、2人盲测；数量是建议门槛，需结合人员与数据覆盖审议。每个集合均需覆盖全部正式类别及负例。

先冻结参与者划分和测试清单，再训练调参；同一人只进入一个集合，同一视频及其相邻帧、裁剪、增强与派生关键点全部继承原集合。按人隔离后再按session检查重复素材与哈希，禁止随机分帧划分。

验证集用于阈值、稳定窗口和模型选择；盲测集不用于调参。因测试结果调整方案时，记录已使用的测试版本，并补充新独立盲测，不反复测试同一集合直到通过。人少阶段可做按人交叉验证探索，不能将其等同于最终独立测试。

保留代码提交、依赖环境、随机种子、清单哈希、词表版本、预处理、训练参数和导出命令。类别不平衡需报告，不能只给总体准确率。

## 7. 模型路线与板端资源门槛

先比较两条可行路线，暂不选定或下载权重：

| 路线 | 先验证内容 | 主要风险 |
| --- | --- | --- |
| 小型图像分类 | 经核实静态类别，候选128/160/224方形输入，背景变化及跨人结果 | 可能记背景/肤色；动态表达无法靠一帧识别 |
| 关键点及时序分类 | 前端能否在P4执行、双手/遮挡/面部是否满足词义、总资源 | PC前端可用不代表板端可用；不能只计算后端分类耗时 |

动态表达需另测短序列路线，计入完整序列缓冲和延迟；静态试验若不适合真实词表，应调整范围或路线。模型算子、量化、许可和运行库与固定组件组合需核对，未经本次明确任务不更换依赖。

模型包应包含输入布局/尺寸/色序、RGB565转换规则、裁剪缩放/补边/归一化、镜像约定、量化scale/zero-point、输出标签、词表版本、拒识阈值、模型hash、运行库版本和许可证。训练与板端必须对同一固定样本比对预处理和输出。

当前主镜像2,877,552 bytes，factory为3,145,728 bytes，余量268,176 bytes（8.53%）。这仅是Flash余量，不是可供推理的RAM预算；大OTA槽不能掩盖factory限制。SD外置仍需评估加载、缺卡及兼容，不提前决定。

板端验证前记录：完整镜像增量、模型存储位置、Internal/DMA/PSRAM峰值及最大连续块、任务栈高水位、端到端P50/P95延迟、显示响应与音频恢复。现有相机帧池、字体缓存、聊天历史和RTC同时占用资源，不能拿独立probe剩余内存作为集成余量。模型阶段采用独立验证工程/分支，不直接塞入当前主线。

## 8. 验收建议（阈值待确认，当前无达标结果）

下面是首轮受限场景MVP建议，需在正式训练前确认并冻结；达标后也不代表连续/开放词汇手语翻译。

| 项目 | 建议门槛或必须行为 | 测量方法 |
| --- | --- | --- |
| 已知类跨人识别 | 宏平均F1≥0.90，每类召回≥0.85 | 盲测按完整独立试验统计，给混淆矩阵、每类支持数及区间 |
| 未知/无动作误接受 | ≤2%，至少200次独立负例试验 | 冻结负例类别和统计窗口；给误接受次数/分母及区间 |
| 候选覆盖与正确性 | 报告拒识率、候选正确率及各类覆盖率 | 不能靠全部拒识满足误接受指标 |
| 量化一致性 | 宏平均F1相对浮点降低≤2个百分点 | 同一冻结清单，记录量化类型和固定样本差异 |
| 板端候选延迟 | 动作完成到稳定候选P95≤1.5秒 | 包含预处理、推理和稳定窗口；动态类单列 |
| 操作响应 | 识别时返回/取消P95≤300ms可见响应 | 资源清理完成另计；不可在UI线程阻塞销毁 |
| 误播保护 | 未确认、低置信度、过渡及取消均不启动播报 | 离线行为检查及用户实机逐项确认 |
| 去重与再表达 | 保持动作只出一次候选；回休息姿态后可表达下一次 | 稳定/解锁阈值用验证集确定 |
| 确认播报 | 精确播确认文字，不扩写；可停止，失败可重试 | 当轮显示/声音用户确认，离线明确提示 |
| 资源恢复 | 5次模式进退后无持续内存下降、无panic/栈溢出 | 相同生命周期点测内存、最大块和栈高水位 |
| 原功能回归 | 欢迎、问答/打断、独立转写、相机返回、设置与息屏正常 | 对应已烧录提交的用户实机回归 |

阈值只是建议；目前没有数据支持已达到。每次记录测试清单版本、参与者匿名分组、硬件/固件/模型hash、条件、次数、失败率和分位数。8h/24h、弱网、极端光照另作专项；不由短测推导通过。
