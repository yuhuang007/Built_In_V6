# P4X 单板双向沟通原型

## 本迭代边界

本阶段只有 P4X 参与运行，不接 CS001 副板、不部署服务器，也不启动 `gateway/`。火山硬件对话智能体是唯一云端语音链路；千帆 Key 与网关只作为后续实验资产保留在工程中，不能被 P4 固件引用。

```text
普通人语音
  -> P4X ES8311 采集（8 kHz / 16-bit / 单声道）
  -> 板载 C6 Wi-Fi
  -> 火山硬件对话智能体（ASR、对话、TTS）
  -> P4X：实时字幕 + 外接扬声器

后续：静态手势
  -> 仅在手语模式启用 MIPI-CSI 摄像头
  -> P4X 本地轻量分类
  -> 候选文字 + 用户确认
  -> 火山 TTS
  -> 外接扬声器
```

## 当前状态机

1. 启动：显示 UI，挂载 SD 字库，初始化 ES8311 和网络。
2. 云端连接完成：显示“网络和音频已就绪”，不再发送任何自动测试文本。
3. 按住说话：停止本地播放、打开麦克风，持续上传 PCM；屏幕更新“对方说的话”的 ASR 字幕。
4. 松开：上传 240 ms 静音尾音，交给云端 VAD 结束本次发言。
5. 云端回答：字幕显示于“即将播报”，PCM 再送扬声器播放。
6. 回到就绪状态：允许下一次按住说话。

同一段 ASR 不允许再调用 `volc_send_text_to_agent()`。这样每一次按住/松开只会触发火山原生语音会话中的一次回复，避免重复回答和日期注入造成的矛盾答案。

## 手语 MVP 约束

摄像头到货后先建立 10--20 个静态手势的可演示版本，候选词优先为：你好、谢谢、请、是、否、需要帮助、再见、喝水、厕所、紧急求助。第一版不做连续手语句子识别。

- 仅在“手语模式”打开摄像头，语音模式不得持有摄像头 DMA 缓冲或运行视觉推理。
- 使用低分辨率、低帧率输入；图像缓冲在 PSRAM 中预分配，且不与音频 DMA 共用。
- 多帧同一分类结果稳定后才显示候选词；用户确认后才调用 TTS。
- 低置信度或多帧不一致显示“未识别，请重试”，不得直接播报。
- 先冻结采集距离、光照、手势朝向、背景和每类样本数，划分独立验证集，再决定量化后的轻量模型是否适合 ESP32-P4。

## 资源与验收

- 音频采集/播放任务优先级高于 UI 和未来视觉任务。
- 继续使用静态字幕缓存，禁止在 RTC 回调栈内分配大数组。
- SD 卡全中文字库按需读取；板载兜底字库只覆盖当前界面与状态文案。
- 构建后必须检查应用二进制在 OTA 分区内至少保留约 24% 余量。
- 音频验收：连续 10 次按住说话、松开发送均有正确字幕和仅一次 TTS 回复，无重启。
- 手语验收：固定距离/光照下的 20 类静态词达到稳定可演示；错误手势不播报。

## 冻结项

本阶段不实现：CS001 UART/副屏、双屏协议、连续手语、网页搜索、天气、千帆网关、云服务器部署。待单板闭环与静态手势验收后，再按原项目的双 MCU 架构接入这些内容。
