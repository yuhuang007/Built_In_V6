# 手语数据集调研与训练路线建议

核对日期：2026年10月10日。用户要求查找国内外数据集，允许自行标注。本次读取公开项目页面和数据集卡；未下载视频、权重或数据包，未申请访问、联系作者、安装训练依赖或开始训练。

## 1. 结论

当前应先确定可取得、可使用、动作与目标规范一致的数据来源，再训练。首批目标仍是经逐词核实的国家通用手语有限词表。优先考虑中文孤立词视频SLR500；申请条件不满足时，CSL-News可作为公开中文候选，但其连续新闻片段需要额外切词与语义核实。所有候选均未确认完整符合国家通用手语，不能仅凭中文标签直接采用。

数据优先保留完整视频：动作顺序、方向、双手关系和必要面部/身体信息可能决定词义。只有经核实的静态类别才适合派生稳定帧。多帧来自同一次动作，不算多个独立试验。

## 4. 用户已有视频与手工标注

此前只读盘点用户本机“手语数据集”目录：basic为235个MP4，common为863个MP4；41个同名项中38个字节相同。抽样容器元数据显示320×240、约1.96–3.4秒。未发现配套许可或标注说明，未核实人物数量、实际动作和来源。视频数量不等于同一词的多人独立样本数量，当前宜作待审核示范素材。

可以人工补充：完整动作起止时间、中文含义/待核实标签、规范来源、匿名人物和拍摄批次、单/双手、遮挡/模糊/裁切、无动作和非词表负例。未确认的动作标为待核实，不能靠猜测强行命名。初期无需手工逐帧标全部21手指关键点，可先自动提取、人工审查失败片段。

获取后先审查少量可用样本及许可，再决定扩大范围；建议先筛5–10个有充分独立示范、经核实的目标词，不强行凑满历史10候选。正式划分按人隔离，原视频及全部派生帧/关键点继承同一集合。背景、服装、重复片段和同一节目来源也要排查，不能随机分帧制造高准确率。

## 5. 建议算法与推进顺序

PC基线建议：完整视频 → MediaPipe双手与上身关键点（词义需要时包含面部信息）→ 坐标/尺度归一化与缺失点掩码 → 小型TCN时序分类，GRU作对照 → 置信度拒识与稳定候选。TCN沿时间建模动作序列。MediaPipe是关键点前端，不直接理解手语词义。YOLOv8n检测手部框不能代替时序语义分类；姿态版本仍需核实精细手指能力。暂不搭建大型自研平台，先用可复现预处理、训练和评估脚本。

这只是推荐实验路线，尚未选定下载权重、训练依赖或板端运行库。P4端必须验证前端、时序后端、图像处理与缓冲的全部资源和算子；PC上的MediaPipe可运行不等于能直接部署到P4。必要时对经核实静态类比较小型图像分类路线，最终以跨人结果与板端实测决定。

建议顺序：确认SLR500申请资格并取得完整协议/词表 → 同时核对已有本机示范来源 → 无申请渠道时审核CSL-News小范围词片段 → 逐词规范核实与许可审查 → 冻结首批标签与按人划分 → 明确训练任务后建立PC基线 → 独立板端资源验证。连续句子翻译和大型预训练延后。

本轮为调研文档：未改固件、锁文件、配置、分区或秘密；未构建、烧录或打开COM20。板上基线仍为8bf0d8e，数据集和推理闭环尚未接入。
