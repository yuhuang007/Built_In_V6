# SC2336 摄像头独立开发计划

## 基线与隔离边界

- 语音稳定标签：`voice-baseline-20261007`
- 摄像头分支：`feature/sc2336-preview`
- 开发板：ESP32-P4X Function EV Board，P4 端口 `COM20`
- 第一阶段使用用户已安装的 SC2336 MIPI-CSI 广角模组。商品信息标称 200 万像素、1080P、120°广角、手动调焦和 ESP32-P4 专用；这些参数仅作为模组选型记录，实际接口与采集能力以探针日志为准。
- 不修改 `master`、语音状态机、音频、SNTP、C6、千帆、网关或服务器。
- 摄像头使用独立程序、独立构建目录和独立配置；失败时可直接回到语音标签。

## 已确认的传感器路线

本机 ESP-IDF v5.5.4 官方 `mipi_isp_dsi` 示例和当前锁定组件均支持 SC2336。第一版采用官方驱动已有的格式：

```text
SC2336
  MIPI CSI-2，2 lane
  24 MHz 输入时钟
  RAW8
  1024×600，30 fps
```

目标管线：

```text
SC2336 RAW8
  → P4 MIPI-CSI
  → P4 ISP
  → RGB565
  → 独立 PSRAM 帧缓冲
  → 后续再交给显示层
```

## 旧实验不能直接恢复的原因

稳定语音源码中保留了一段由 `#if 0` 隔离的 V4L2/MMAP 预览实验。该实验曾直接打开 ISP 节点并请求 RGB565，但稳定配置关闭了 ISP pipeline controller，且在节点与格式尚未枚举清楚前就进入 LVGL 预览。因此不能简单移除 `#if 0` 或重新打开摄像头按钮。

旧代码只作为失败路径参考；新实现以 ESP-IDF v5.5.4 官方示例、当前 BSP 和实际日志为准。

## 分阶段验收

### 阶段 1：传感器识别与无显示采集

1. 建立独立摄像头探针程序和 `sdkconfig.camera`。
2. 只启用 SC2336、MIPI-CSI、ISP 和必要的 PSRAM 配置。
3. 输出传感器 PID、可用格式、实际选中格式、帧数、帧率、缓冲大小和剩余 PSRAM。
4. 连续采集 60 秒；不初始化 RTC、Wi-Fi、音频或 LVGL。
5. 不记录或保存画面内容。

通过条件：识别 SC2336，使用预期 RAW8 格式，连续 60 秒有稳定帧计数，无重启、超时或内存持续下降。

#### 2026-10-07 实机验收结果：通过

- 模组已由用户更换为商品标称的 SC2336 MIPI 版本。
- 传感器 PID：`0xcb3a`；SCCB 地址：`0x30`。
- 实际选择格式：`MIPI_2lane_24Minput_RAW8_1024x600_30fps`。
- CSI 配置：2 lane，lane rate 288 Mbps。
- ISP 输出缓冲格式：RGB565；单帧缓冲 1,228,800 字节。
- 连续采集 60 秒，共完成 1,802 帧，实测约 29.98 fps。
- 剩余 PSRAM 稳定在 31,092,476 字节，无持续下降。
- 采集期间无重启、超时或卡死，最终日志为 `PASS: captured 1802 frames continuously for 60 seconds`。

结论：阶段 1 的“传感器识别与无显示采集”通过。当前结果同时证明 CSI/ISP 能持续产出 RGB565 帧，但尚未通过屏幕观察验证画面方向、颜色、比例及 RGB565 字节序，因此不能视为阶段 2 或实时画面预览全部完成。

### 阶段 2：ISP 输出验证

1. 输入保持 RAW8 1024×600。
2. 启用 P4 ISP 输出 RGB565。
3. 使用预分配 PSRAM 缓冲，不在回调栈分配大数组。
4. 验证每帧尺寸、步幅、字节序和缓存同步。

通过条件：RGB565 帧大小和格式稳定，连续 60 秒无错误帧、无泄漏。

### 阶段 3：独立屏幕预览

1. 在摄像头程序内接入显示，不接入语音 UI。
2. 首先低刷新率显示，再逐步提高；音频任务仍不参与。
3. 完成连续 60 秒预览和 5 次启动/停止。

通过条件：画面方向、颜色和比例可接受；5 次启停后 PSRAM、CSI、ISP 和显示资源均正常释放。

### 阶段 4：评估与语音共存

只有前三阶段通过后才评估摄像头与语音共存。共存设计必须保证音频任务优先，摄像头按模式启停，视觉缓冲与音频 DMA 隔离。未经单独回归，不合并回 `master`。

## 每次迭代的固定顺序

```text
确认工作区干净
  → 只修改摄像头子系统
  → 本地提交
  → 使用工程 .idf-build-env 和 tools/Invoke-P4Build.ps1 构建
  → 检查 dependencies.lock 与分区余量
  → 烧录 COM20
  → 实机验收
  → 记录结果
```

任何失败都先保留日志和提交，不使用 `git reset --hard` 或 `git checkout --`，也不通过修改 C6、网络或语音代码绕过摄像头问题。
