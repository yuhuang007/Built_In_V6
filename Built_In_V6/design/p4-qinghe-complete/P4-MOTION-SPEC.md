# 青禾 / ESP32-P4 动效落地规范

本文件为后续固件实现方案。原型可演示视觉与状态；下列频率和资源是设计预算，不是 P4 实测结果。本轮不改变现有硬件/显示链路。

## 1. 页面与导航

600×1024 竖屏；显示方向保持现状，相机方向独立。首页卡片进入语音、转写和相机，右上进入设置。语音/转写/相机/设置返回首页；Wi-Fi/帮助/关于返回设置。不设置底部导航栏。

正文及内页标题 28px。使用真实字体 line_height（当前 28px 字体为 54px、baseline 偏移16），不按名义字号缩小控件。输入框64px，候选行至少 line_height+8；父区域裁剪、内边距和换行在真实字库上复查。欢迎、确认框和启动新增文字须检查实际字形覆盖。

## 2. 动效表

| 场景 | 设计效果 | 设计预算 | 事件/结束条件 |
|---|---|---|---|
| 开机 | 禾苗9×9点阵逐行点亮，三段实色状态 | 8Hz；仅点阵与状态区域变化 | 显示/字体/音频/连接真实准备事件 |
| 欢迎 | 小范围短条起伏，文字静态 | 8Hz | 实际欢迎音频播放结束，保留完整欢迎保护 |
| 前进/返回 | 一块不透明纸幕遮盖150ms、揭开170ms，返回反向 | 目标20Hz，约6–8帧；仅一块幕对象 | 遮盖完成再安全提交新页，资源交接完成再揭开 |
| 键盘 | 嵌入式高度展开或收回 | 180ms；目标20Hz | 更新阅读视口，保持跟随/上翻策略 |
| 候选 | 独立预留区域短距离进入 | 150ms；目标20Hz | 不覆盖录音、输入和正文 |
| 确认框 | 10px局部位移与有限透明变化 | 160ms；目标20Hz | 关闭后恢复焦点、阅读位置；确认才清空 |
| 录音/回应 | 状态文字与5–7根短条 | 8Hz，只改局部 | 真实录音/回应/打断事件 |
| 息屏 | 黑屏静止；唤醒用同一有限切页原语 | 无空闲动画 | 首次输入仅唤醒，业务忙碌沿用既有限制 |
| 减少动态效果 | 直接显示终态，用文字反馈 | 不运行持续动效 | 同样保留交互和资源门禁 |

浏览器使用单个50ms定时泵计算有限动画，结束即移除任务；局部状态在泵内按125ms节拍更新。浏览器调度可能延迟，所以320ms是设计时长，不保证精确320ms。浏览器被隐藏时短条不继续改DOM；不可据此宣称所有计时器均暂停。

纸幕中央的禾苗不包含业务正文，遮盖期间不接受第二次导航。有限过渡完成后释放幕。不得同时创建旧/新全屏截图，不使用全屏透明交叉淡化、blur、视频/GIF或粒子。正常空闲页面无持续装饰动画。

## 3. 启动真实事件与保护

现有 main.c 的 startup_status_timer 使用字体、base、audio、Wi-Fi/network prepared 等真实标志。当前 fonts_done 且网络就绪或超时策略满足后才能结束准备，并保留异常fallback；不得用原型的3.4秒/5.3秒计时替换现有规则。浏览器约六秒是加速演示；上轮记录实机首页约30秒、PCM约34秒，仅为当次历史观察，不是本轮测试。

现有独立启动screen防止被覆盖首页提前触发SD取字阻塞。SD字体尚未ready前，只使用内置 lv_font_startup_zh 已覆盖的字符；新增启动文案须审查字子集，不能为了动画触发大字库同步读取。三段状态表达“显示、声音与文字、连接”，只在对应资源真正满足后推进，不显示伪百分比。离线按现有退让策略进入首页，提示连接但不伪造欢迎播报。

实际首页可见后的下一UI周期才允许云欢迎；欢迎由播放完成事件解除门禁。录音、弹窗、模式切换和息屏的状态机不能由动画完成事件替代。2秒尾静音、完整欢迎、启动及息屏保护不变。

## 4. 已核查的工程约束

依据 firmware/p4_main/sdkconfig.sign、main/main.c 与 main/portrait_display.c（源码基线1d56520）：

| 项目 | 当前值/估算 | 含义 |
|---|---|---|
| LVGL 色深 | RGB565 / 16bit | 不引入全屏RGBA资源 |
| LVGL刷新周期 | 默认33ms；现有启动期80ms | 不为了原型改变系统刷新配置 |
| LVGL绘制缓冲 | buffer_size=600×160，double_buffer=true | 600×160×2×2 = 384000B，按像素尺寸估算 |
| LCD scanout缓冲 | 两块全屏RGB565 | 600×1024×2×2 = 2457600B，现有分配 |
| 每份额外截图 | 600×1024×2 = 1228800B | 过渡新增全屏截图预算为0B |
| PSRAM | 配置200MHz | 不等于可任意增加内存带宽 |
| 显示模式 | 非direct/full_refresh，现有sw_rotate/最终90°旋转 | 不更改显示方向或刷新链路 |

编辑/候选区域已有CPU同步复制/旋转回退，小于4096像素区域也走CPU，其他区域使用现有PPA旋转策略。保持这些路径以及缓存同步、完整行处理、VSYNC retirement。不能因为有PPA就认为切页免费，也不能将动画区域改回PPA来换帧率。

实色幕移动仍可能造成大面积脏区；现有旋转/复制成本也不只由矩形面积决定。20Hz是候选预算，上板若显示带宽或音频不足，先取消大范围横移，降为局部短提示/减少动态效果；禁止靠增加双份截图或全屏alpha解决。

9×9点阵在原型以81个SVG圆表示；LVGL建议使用一个custom draw对象与11字节bitmask表示81位，不创建81个独立对象。小波形同样单对象绘制，不进行字体重排。所述11字节仅为图案数据，不是整个对象/渲染器RAM开销。新增对象、栈和Flash总增量需要移植后真实测量。

历史最近sign镜像为3006144B，最小factory应用槽3145728B，余139584B（第16/20节，非本轮新构建）。不新增大位图/视频、不升级依赖或改分区。实际移植时先标准构建并复核实际余量，不能用历史数字代替。

## 5. 业务与生命周期

- 导航由单个过渡拥有者管理，期间禁用重复导航；关闭/失败也必须释放幕、恢复输入。资源交接未完成不得揭示已就绪界面，不叠加第二个相机/语音会话。
- 保存阅读状态与草稿后切页。异步回调核对对象仍存在、页面仍匹配；停止关联动画后再销毁对象。
- 转写在底部跟随，上翻保留偏移；识别结果持续修订缩短时夹到有效范围，不能因此强行恢复跟随。键盘高度变化也用同一策略。
- 回到最新在正文下独立栏，候选在输入上方预留。USB输入保持64px输入区，不自动弹软键盘或抬整页。
- 清空沿用现有识别中限制；弹窗期间保护输入，取消保留内容与位置，确认清空后可继续业务。失败草稿保留。
- 录音、相机、网络、音频是业务事件。HTML示例数据/定时回复只用于评审，不移植为正式功能逻辑，不新增持久化或产品测试菜单。

## 6. 后续固件验收门槛

后续需另行授权和实现，本轮未执行：

1. 用真实字库核对启动子集、28px正文/确认框及候选的完整字形和裁剪；触屏/USB展开收起不挡正文和主操作。
2. 反复切换语音、转写、相机、设置，检查资源交接、草稿、阅读位置、动画任务取消和首触唤醒。
3. 比较动画开/关的UI回调间隔、显示欠载、内外部最大连续空闲块和任务栈；总空闲不能替代连续块。计数/时间指标不等于实屏FPS。
4. 进行短时欢迎/录音/回复并发观察，确认完整欢迎、2秒尾静音、音频无可闻中断；以用户触屏目视和听觉验收为准。
5. 按工程标准流程提交相关代码、build -Profile sign，检查锁/config/最小应用分区余量，获得烧录授权后才flash。异常停止，不改依赖/分区救场。
